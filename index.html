Nginx acts as a reverse proxy — routes all HTTP traffic to the right process

Protocols

ProtocolFull NameUse Case
TCPTransmission Control ProtocolReliable, ordered delivery — web, email
UDPUser Datagram ProtocolFast, one-way — video/audio streaming
ICMPInternet Control Message ProtocolDiagnostics — ping, traceroute

Analogy: TCP = certified mail (you get a receipt). UDP = shouting across a room — fast, no guarantee they heard you.

⚙️ Servers & Nginx
💡
A server is simply a program that serves requests. Request flow: Browser → Nginx (80/443) → Node.js (3000) → Database

Nginx — The Reverse Proxy

CommandWhat it does
sudo apt install nginxInstall Nginx
sudo service nginx startStart the Nginx service
less /etc/nginx/sites-available/defaultView default config
/etc/nginx/sites-enabled/<config>Your custom proxy config lives here
💡
Nginx receives all traffic on port 80/443, then forwards internally to your app. Your app port is never directly exposed to the internet.

🔒 Security

Defense in Depth

1SSH key auth — Key pairs instead of passwords. Passwords can be brute-forced; private keys cannot
2Disable root login — Attackers always try root first. Remove that attack surface
3Firewall (UFW) — Block all ports except what you explicitly need
4Auto-updates — Most breaches exploit known, already-patched vulnerabilities

File Permissions

💡
chmod format: [owner][group][others] where 4=read, 2=write, 1=execute. So 644 = owner rw (6), group r (4), others r (4).
chmod 644 ~/.ssh/authorized_keys   # correct for SSH keys
stat -c %a <file>                  # view numeric permissions

UFW — Uncomplicated Firewall

CommandWhat it does
sudo ufw statusShow current firewall rules
sudo ufw allow <port>Open a port
sudo ufw deny <port>Block a port
sudo ufw enableActivate the firewall
nmap <IP>Scan open ports on a server
less /etc/servicesList all well-known port numbers

SSH Hardening Steps

# 1. Set correct key permissions
chmod 644 ~/.ssh/authorized_keys

# 2. Disable root login
sudo vi /etc/ssh/sshd_config
# Set: PermitRootLogin no

# 3. Restart SSH daemon to apply changes
sudo service ssh restart
⚠️
Before disabling root login, verify your non-root sudo user can SSH in — or you'll lock yourself out permanently.

🗄️ Databases

Relational vs Non-Relational

Relational (SQL)

Structured tables, defined schemas, data linked via foreign keys. Best for complex queries and data integrity.

MySQLPostgreSQLSQLite
Non-Relational (NoSQL)

Flexible schema — documents, key-value, graphs. Best for high-speed reads/writes or unstructured data.

RedisMongoDBCassandra
💡
Redis = in-memory key-value store. All data in RAM → extremely fast. Used for caching, sessions, leaderboards.
🏗️ Architecture

Monolith vs Microservices

Monolith

All features tightly coupled, deployed as one unit. Simple to start; hard to scale specific parts independently.

Microservices

Loosely connected services, each with one responsibility. Independently deployable — but more operational complexity.

Load Balancing Algorithms

AlgorithmHow it works
Round RobinEach server gets a request in turn, cyclically
IP HashingSame client IP always goes to same server (good for sessions)
Least ConnectionsRoute to server with fewest active connections
Least LoadRoute to server under least CPU/memory pressure
Random ChoicePicks a server at random
